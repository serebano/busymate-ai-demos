How the thread reaches the helpdesk

The same brain and tools as the window above, delivered the way Slack's Events API actually works.

1

Someone mentions the bot

A teammate writes @Patch in #it-help or opens a DM. The team always starts the conversation; the helpdesk never posts unasked.

2

Slack delivers the event

The mention arrives at the workspace's Events URL, its signature is checked, and it becomes a visitor turn with the same tool floor as the web chat — no platform tools ever reach a Slack user.

3

Patch answers in the thread

Catalogue, status, a ticket card or a hand-off — posted as a threaded reply, so the channel stays readable and an engineer can pick the thread up.

Before you invite the bot

A few things teams ask first

Do we need to install anything on our laptops?
The Patchwell app (menu-bar on macOS, tray on Windows) handles VPN, printers and enrolment; it ships pre-installed on any laptop Patchwell provisions, and existing laptops enrol in about five minutes.
Can Patch see our Slack messages?
Only the messages that @-mention it or are sent to it directly; it never reads other channels.
What happens if the whole office loses internet?
That's a P1 — the on-call engineer is paged within 15 minutes, and status updates go to #it-help from the engineer's phone until it's back.
Do you support Windows and Linux as well as macOS?
macOS and Windows fully; Linux laptops are supported for access, VPN and the security baseline but not for the loaner programme.
Can we keep our existing IT person?
Yes — many teams use Patchwell as the first line and escalate to their own person or vendor; the hand-off is a mention in the thread.
Patchwell is a demonstration helpdesk. No ticket is actually worked, no engineer is paged, and the customer behind the sign-in button is not a real person.
